INFRASTRUCTURE / INDEPENDENT LAB

Enterprise-style home lab

A platform for continued education and experimentation across interconnected IT services.

Purpose and scope

The home lab brings identity, virtualization, networking, endpoint policy, and backups into one learning environment. It is described in my professional profile as an independent, ongoing project, with automation and recovery workflows that simulate real-world IT scenarios.

Documented building blocks

  • Identity and access: Windows Server identity and remote management services.
  • Workloads: virtual machines and containers on Proxmox and UnRAID.
  • Practice areas: networking, endpoint policy, automation, and recovery workflows.

Related hands-on toolkit

The public technical profile also lists Active Directory, SMB, and RDP; Docker stacks; PowerShell, Bash, and Batch; Microsoft 365 and Intune policy testing; VLAN segmentation and firewall configuration; and layered backup tools including VEEAM and Windows Backup Services. Those are documented skill areas, not a claim that every tool runs in a single lab topology.

Engineering focus

The focus is practice with the dependencies between infrastructure services rather than a standalone application: identity and remote access, VM and container workloads, policy, and recovery. The public project description identifies automation and recovery workflows as lab practice; it does not publish per-workload operating procedures.

Evidence and limits

This case study summarizes the public project description and technical toolkit. It does not claim a production deployment, a particular network topology, service-level targets, measured uptime, cost savings, or benchmark results. No such measurements are published here.
