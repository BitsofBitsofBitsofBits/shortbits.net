Building shortbits.net

One repository, two public experiences, and an authenticated content workflow.

Purpose and scope

shortbits.net is my personal web platform and a learning project. The root chooser leads to a playful, terminal-themed internet presence or a professional profile. The two experiences share site assets and saved accessibility preferences without requiring the professional profile to load the desktop games and Easter eggs.

Implementation

  • Frontend: HTML, CSS, and JavaScript, with root-relative shared assets and responsive layouts.
  • Content: Supabase-backed profile information and blog posts, managed through an authenticated admin center.
  • Private contact: a Supabase Edge Function with server-side validation, a honeypot, rate limits, and optional Turnstile verification.
  • Delivery: GitHub Actions validation and deployment, with the source available in a public repository.

Publishing without a frontend framework

The blog keeps Markdown in Supabase. At deployment, a Node script fetches published, due posts using public read permissions and generates individual HTML articles, an RSS feed, archive links, and sitemap entries. The build reuses the same Markdown renderer as the browser so formatting rules are shared.

The live archive can still show a newly published post through the legacy query-string reader before the next deployment. This is a deliberate trade-off: saving in the admin center does not automatically rebuild the site. Static pages, feed entries, and search metadata change at deployment; unpublishing also requires deployment to remove an existing static copy.

Accessibility and content boundaries

The site includes reduced-motion, increased-contrast, and larger-text preferences, semantic page landmarks, skip links, and an accessible Markdown preview. Blog Markdown is rendered as text and explicitly supported elements rather than inserted as arbitrary HTML. Supabase row-level policies separate public published posts from authenticated editing.

Evidence and limits

The public source repository documents the implementation, schema migrations, and validation scripts. These are implementation details, not claims of measured traffic growth, conversion gains, performance improvements, or a formal accessibility certification.
